# 미션16 디버깅/오류 해결 기록

## 오류 로그
- 날짜: 2026-03-10
- 실행 셀: `modeling.ipynb` ONNX export 셀 (`torch.onnx.export`)
- 오류 메시지:
  - `Failed to convert the model to the target version 17 using the ONNX C API. The model was not modified`
  - `RuntimeError: ... axes_input_to_attribute.h:65 ... Assertion 'node->hasAttribute(kaxes)' failed`
  - (참고 경고) `FutureWarning: isinstance(treespec, LeafSpec) is deprecated`
  - (참고 경고) `axis name: seq will not be used ...`

## 원인 분석
- `torch.onnx.export(..., opset_version=17)` 과정에서 내부 버전 변환기가 일부 연산 그래프(axes 속성 처리)를 17로 다운컨버전하지 못함.
- 즉, "모델 자체 추출 실패"가 아니라 "타깃 opset 17로의 변환 단계 실패" 이슈.

## 해결 방법
- 로그 마지막에 `Saved: ... mission_16_qtranslator_1.7b_v2.onnx`가 출력되어 ONNX 파일은 생성됨을 확인.
- 생성된 ONNX의 실제 opset을 확인하고(`onnx.load(...).opset_import`) ONNX Runtime 추론으로 동작 검증.
- 과제 요구가 "ONNX 형식" 중심일 경우, 실제로 동작하는 opset(예: 18/19)을 유지하고 보고서에 17 다운컨버전 실패 사유를 명시.
- 과제에서 opset 17 고정 요구가 있을 경우에만 버전 조합(onnx/onnxscript/torch) 조정 후 재시도.

## 검증 결과
- `torch.onnx` 로그 상 그래프 최적화 완료(`Optimize ... ✅`) 및 파일 저장 완료 확인.
- 후속 `inference.ipynb`에서 ONNX Runtime 추론 경로로 결과/시간 비교 가능 상태.

## 재발 방지
- Export 직후 아래 체크를 반드시 수행:
  - 실제 opset 확인
  - ONNX checker 통과 여부
  - 최소 1개 샘플 추론 테스트
- 보고서에 "경고/실패 로그"와 "실제 동작 검증 결과"를 함께 기록해, 치명 오류와 비치명 경고를 구분.

## 오류 로그 (ONNX checker Serialize 에러)
- 날짜: 2026-03-10
- 실행 셀: `inference.ipynb` ONNX 검증 셀
- 오류 메시지:
  - `EncodeError: Failed to serialize proto`
  - 발생 위치: `onnx.checker.check_model(onnx_model)`

## 원인 분석
- `mission_16_qtranslator_1.7b_v2.onnx`는 외부 데이터(`.onnx.data`)를 사용하는 대용량 ONNX 모델.
- 이때 `onnx.checker.check_model(onnx_model)`처럼 **모델 객체**를 넘기면 내부에서 `SerializeToString()`을 수행하는데, 대용량 external-data 모델에서 직렬화 단계가 실패할 수 있음.

## 해결 방법
- checker에 모델 객체 대신 **파일 경로**를 전달:
  - `onnx.checker.check_model(cfg.onnx_path.as_posix())`
- 필요 시 구조 확인만 할 때는 아래처럼 외부 데이터 로드를 끄고 사용:
  - `onnx.load(cfg.onnx_path.as_posix(), load_external_data=False)`

## 검증 결과
- 경로 기반 checker 호출 시 `ONNX check: OK` 확인 가능.
- 모델 자체가 손상된 것이 아니라 checker 호출 방식(객체 직렬화 경로) 이슈임을 확인.
