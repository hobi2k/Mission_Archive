# 미션 18 서비스 구조 및 ERD

## 1. 전체 서비스 구조

본 서비스는 Streamlit 프론트엔드와 FastAPI 백엔드를 분리한 구조로 설계했다. 사용자는 Streamlit 화면에서 영화 정보와 리뷰를 입력하고, 프론트엔드는 해당 요청을 FastAPI 백엔드로 전달한다. 백엔드는 요청을 처리한 뒤 SQLite 데이터베이스에 결과를 저장하며, 리뷰 등록 시에는 감성 분석 모델을 호출해 감성 라벨과 점수를 함께 기록한다.

전체 구조는 다음과 같다.

사용자 요청은 Streamlit 프론트엔드를 거쳐 FastAPI 백엔드로 전달되고, 백엔드는 SQLite 데이터베이스와 감성 분석 모델을 함께 사용해 응답을 반환한다.

이 구조를 선택한 이유는 프론트엔드와 백엔드의 책임을 분리하면서도, 과제 요구사항에 맞는 단순하고 명확한 서비스 흐름을 유지하기 위해서이다.

## 2. 요청 흐름

### 영화 등록 흐름

영화 등록 기능은 사용자가 Streamlit 폼에 영화 제목, 개봉일, 감독, 장르, 포스터 URL을 입력하면 시작된다. 프론트엔드는 이 데이터를 `POST /movies` 요청으로 백엔드에 전달하고, 백엔드는 검증 후 SQLite에 데이터를 저장한다. 저장된 영화 정보는 다시 프론트엔드로 전달되어 영화 목록에 반영된다.

사용자 입력 → Streamlit 영화 등록 폼 → POST /movies → SQLite 저장 → 등록 결과 반환

### 리뷰 등록 및 감성 분석 흐름

리뷰 등록 과정에서는 사용자가 특정 영화를 선택하고 작성자 이름과 리뷰 내용을 입력한다. 프론트엔드는 이를 `POST /reviews` 요청으로 전송하고, 백엔드는 리뷰를 저장하기 전에 감성 분석 모델을 호출한다. 분석 결과로 감성 라벨과 감성 점수를 얻은 뒤, 리뷰 데이터와 함께 SQLite에 저장한다. 이후 프론트엔드는 다시 렌더링되며 최근 리뷰 목록과 평균 평점이 즉시 갱신된다.

사용자 입력 → Streamlit 리뷰 등록 폼 → POST /reviews → 감성 분석 모델 추론 → 리뷰와 감성 결과 SQLite 저장 → 등록 결과 반환 → 프론트엔드 재렌더링

## 3. 프론트엔드 구조

프론트엔드는 `frontend/app.py` 한 파일을 중심으로 구성했다. 이 파일은 백엔드 연결 확인, 영화 목록 조회, 영화 등록, 리뷰 등록, 감성 결과 표시, 최근 리뷰 표시 기능을 담당한다.

프론트엔드는 `frontend/app.py`를 중심으로 구성했고, 백엔드 연결 확인, 영화 목록 조회와 카드 표시, 영화 등록 폼, 리뷰 등록 폼, 감성 분석 결과 메트릭 출력, 최근 10개 리뷰 표 출력 기능을 담당한다.

프론트엔드는 자체적으로 데이터를 저장하지 않으며, 모든 상태는 FastAPI 백엔드에서 관리한다. 이 방식은 과제 요구사항에 포함된 “모든 데이터는 백엔드에서 관리” 조건을 충족하기 위한 설계다.

## 4. 백엔드 구조

백엔드는 기능별로 파일을 나누어 구성했다. `main.py`는 FastAPI 엔드포인트를 정의하고, `crud.py`는 데이터베이스 처리 로직을 담당하며, `sentiment.py`는 감성 분석 모델 실행을 맡는다. `models.py`는 SQLAlchemy ORM 모델을 정의하고, `schemas.py`는 요청 및 응답 스키마를 정의한다.

백엔드는 `main.py`에서 FastAPI 엔드포인트를 정의하고, `crud.py`에서 영화와 리뷰에 대한 CRUD 및 평균 평점 계산을 수행한다. `sentiment.py`는 Transformers 기반 감성 분석을 담당하며, `models.py`와 `database.py`는 각각 SQLAlchemy 모델 정의와 SQLite 연결을 담당한다.

이와 같은 분리 구조를 통해 API 정의, 비즈니스 로직, 데이터베이스 모델, 감성 분석 로직을 각각 독립적으로 관리할 수 있도록 했다.

## 5. 데이터베이스 구조(ERD)

서비스의 핵심 데이터는 `Movie`와 `Review` 두 테이블로 구성된다.

- Movie
  - id: INTEGER PK
  - title: VARCHAR(200) UNIQUE
  - release_date: DATE
  - director: VARCHAR(100)
  - genre: VARCHAR(100)
  - poster_url: VARCHAR(500)
  - created_at: DATETIME

- Review
  - id: INTEGER PK
  - movie_id: INTEGER FK -> Movie.id
  - author: VARCHAR(100)
  - content: TEXT
  - sentiment_label: VARCHAR(20)
  - sentiment_score: FLOAT
  - created_at: DATETIME

두 테이블의 관계는 `Movie` 1 : N `Review` 형태이다. 하나의 영화는 여러 리뷰를 가질 수 있으며, 하나의 리뷰는 하나의 영화에만 속한다. 이 관계를 통해 영화별 리뷰 조회와 평균 평점 계산을 자연스럽게 처리할 수 있다.

## 6. 평균 평점 계산 구조

리뷰 감성 분석 결과는 0에서 1 사이의 점수로 정규화되어 저장된다. 영화별 평균 평점은 각 리뷰의 `sentiment_score` 평균을 계산한 뒤 5점 만점 기준으로 환산하여 표시한다.

평균 평점은 평균 감성 점수에 5를 곱하는 방식으로 계산한다.

이 방식은 감성 분석 결과를 사용자에게 보다 직관적인 평점 형태로 보여주기 위해 적용했다.

## 7. 설계 의도

이번 프로젝트에서 사용한 기술 선택은 과제 요구사항과 실행 안정성을 중심으로 결정했다.

- SQLite는 별도의 DB 서버 없이 파일 하나로 데이터를 관리할 수 있어 제출과 시연에 적합했다.
- SQLAlchemy는 데이터베이스 테이블을 파이썬 클래스처럼 다룰 수 있어 구조를 명확하게 유지하는 데 도움이 되었다.
- Transformers 기반 감성 분석 모델은 리뷰 분류 목적에 직접적으로 적합했고, 대형 생성형 모델보다 가볍게 실행할 수 있었다.
- Streamlit과 FastAPI를 분리함으로써 화면 구성과 데이터 처리 책임을 명확하게 나눌 수 있었다.

결과적으로 이 구조는 영화 정보 관리, 리뷰 저장, 감성 분석, 평균 평점 표시라는 핵심 기능을 안정적으로 구현하기에 적절한 형태였다.
